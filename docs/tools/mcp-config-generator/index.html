What is an MCP config?

The Model Context Protocol (MCP) is the open standard AI apps use to connect to tools: GitHub, a browser, your database, your issue tracker. Each tool runs as an MCP server. Your AI app (the client) finds its servers in a small config file: a name for each server, plus either the command that starts it on your computer (a local server) or the URL it lives at (a remote server).

The idea is the same everywhere, but every app spells the file differently: a different file name and location, a different top-level key, different names for the URL field and a different way to read secrets. That's the part this tool takes care of.

Where is claude_desktop_config.json?

  • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows: %APPDATA%\Claude\claude_desktop_config.json
  • Linux: ~/.config/Claude/claude_desktop_config.json

The easy way: in Claude Desktop open Settings → Developer → Edit Config. The file only starts local servers. To add a remote server, use Settings → Connectors → Add custom connector, or bridge it with npx -y mcp-remote <url> (the generator does this for you). Quit and reopen Claude Desktop after every change.

Local or remote server?

Remote servers run on the service's side: you paste a URL and sign in with OAuth. Nothing to install, nothing to update, and no key sitting in a file. GitHub, Linear, Notion, Sentry, Stripe, Figma, Atlassian, Vercel, Cloudflare and Supabase all have official remote servers. Local servers run on your computer through npx, uvx or docker. You need them when the tool works with your machine: files, a browser, git, a local database.

Keep API keys out of your config

Config files get committed, shared in screenshots and pasted into chats. This generator never puts a key in the file: it writes a reference like ${GITHUB_PAT} (or each app's own version of it), and shows you the one command that sets the variable on your computer. VS Code gets an inputs prompt instead, so it asks once and stores the key securely. Three apps (Claude Desktop, Antigravity and Zed) can't read variables in their config; for those you get a clear <PLACEHOLDER> to fill in, in a file that should stay on your machine.

Example: the same server in three apps

GitHub's official remote server with a personal access token read from GITHUB_PAT:

Claude Code (.mcp.json)

{
  "mcpServers": {
    "github": {
      "type": "http",
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer ${GITHUB_PAT}" }
    }
  }
}

Cursor (.cursor/mcp.json)

{
  "mcpServers": {
    "github": {
      "url": "https://api.githubcopilot.com/mcp/",
      "headers": { "Authorization": "Bearer ${env:GITHUB_PAT}" }
    }
  }
}

Codex (~/.codex/config.toml)

[mcp_servers.github]
url = "https://api.githubcopilot.com/mcp/"
bearer_token_env_var = "GITHUB_PAT"

FAQ

How do I add an MCP server to Claude Code?

Run claude mcp add in your terminal, for example claude mcp add --transport http linear https://mcp.linear.app/mcp for a remote server, or claude mcp add playwright -- npx -y @playwright/mcp@latest for a local one. Add --scope project to save it in .mcp.json so your team gets it too. This tool writes the commands for you.

Where is claude_desktop_config.json?

On macOS: ~/Library/Application Support/Claude/claude_desktop_config.json. On Windows: %APPDATA%\Claude\claude_desktop_config.json. On Linux: ~/.config/Claude/claude_desktop_config.json. The quickest way to open it is Settings → Developer → Edit Config in Claude Desktop.

Is Cursor's mcp.json the same as VS Code's?

No. Cursor uses "mcpServers" in .cursor/mcp.json and reads secrets with ${env:NAME}. VS Code's .vscode/mcp.json uses "servers", needs a "type" on every server, and can prompt for secrets with an "inputs" list. The newer Copilot format (mcp-config.json) goes back to "mcpServers". Paste one into the converter on this page to get the other.

How do I add MCP servers to Codex?

Codex reads TOML, not JSON: add a [mcp_servers.<name>] table to ~/.codex/config.toml with command and args for a local server, or url for a remote one. Keys go in env_vars or bearer_token_env_var so they are read from your environment. You can also run codex mcp add. The same config is used by the Codex CLI, the IDE extension and the app.

Why won't my MCP server start?

The usual causes: npx without -y waiting for an install prompt, a Node.js version that is too old, docker run without -i, a remote URL without "type": "http" in Claude Code, or an environment variable that isn't set in the app's environment. Restart the app after every change. Paste your config into the checker on this page to find these.

Should I use a remote or a local MCP server?

If the service has an official remote server (GitHub, Linear, Notion, Sentry, Stripe, Figma…), use it: nothing to install, it updates itself, and you sign in with OAuth instead of storing a key. Use a local server when it needs your machine: files, a browser, git, or a database on your network.

Does this tool upload my config?

No. The generator, converter and checker run entirely in your browser. Nothing you paste or type is sent anywhere.
